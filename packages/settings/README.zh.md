# @roubaai/settings

[English](README.md) | 中文

## 概述

`@roubaai/settings` 持有媒体栈的配置面。它的宿主机半场注册 `roubaai-video-plugin` 设置命名空间，并通过本插件自己的受限 JSON 路由提供服务；浏览器半场贡献设置页面区块，供人配置一个提供方行 —— 它的密钥、端点、模型与 **适配器** —— 并执行连接测试。媒体提供方在每次操作时读取这些值，因此在页面上修改无需重启、也无需改动环境变量。适配器正是用来选用后端的：可以同时挂载多个，工具只会路由到当前激活行所指名的那个。当某个部署希望让使用者从浏览器配置媒体生成、而不是去导出 API key 时，选择本包。

<a id="use-this-package"></a>
## 使用本包

把这一行与它所配置的媒体行一起挂载。该行注入 `webServer` 与 `settings`，因此只能挂载在同时具备这两者的组合里。

```yaml
- id: roubaai-settings
  name: '@roubaai/settings'
  inject: [webServer, settings]
```

该行自身不接受配置；它管理的每个值都在设置页面上编辑。浏览器半场加载后，区块出现在设置页中；保存会写入命名空间的值，**测试连接**则用卡片上显示的值（含尚未保存的密钥）执行探测。

| 字段 | 作用 |
|---|---|
| API key | `secret` 角色字段：只写入，绝不回传浏览器。页面只显示"是否已保存"，不显示其值。 |
| 适配器 | 处理该行的后端：下拉显示目录里的显示名（`ark` → 火山引擎、`maizi` → 麦子AI、`mxapi` → MxAPI），保存的是注册表名。可选值来自本次部署实际挂载的适配器（读自 `ctx.media`）；若某行存的适配器已不再挂载，它会作为唯一选项保留，因此编辑不会静默改掉该行的目标。留空解析为该类别的内置适配器。 |
| 端点基址 | 覆盖提供方的默认 API 基址；留空表示使用提供方默认值。 |
| 图像模型 / 视频模型 | 覆盖每次生成所用的模型；留空表示使用提供方配置的默认值。该控件是自由文本输入框，下方列出后端当前目录（经 `models.list` 读取）：厂商模型 id 带日期段且会退役，部署必须能迁到仍在售的 id，而不必把内置行改成自定义提供方。不支持列模型的后端，仍以手动输入为准。 |
| 分辨率档位 | 这一行的每次生成要用的档位；留空表示跟随默认档位（2K）。选项**就是**所选模型自报的档位，所以"模型不支持这个档位"的组合根本选不出来；已存但该模型不再声明的值会保留显示，保存时被拒绝并说明原因。后端不上报档位时（如麦子AI），这一项不出现。 |

模型目录里的每个候选还会直接带上**它自己的能力**：可用档位、参考图上限、支持比例 —— 这些都来自后端自己的上报，页面只负责显示，不另抄一份。

### 怎么选：模型 × 档位

| 想要的效果 | 选什么 |
|---|---|
| 轻量试构图、快速迭代 | lite 档 + 2K |
| 1.5K 中间档 | pro 档 + 1.5K |
| 大图细节 | lite 档 + 3K / 4K |
| 精细编辑 / 多图参考 / 图层拆分 | pro 档 |

模型 id 带日期段且会退役，所以这张表说的是**档位类**（lite / pro），不是某个具体 id：具体 id 以设置页当前读到的目录为准。默认行是 lite 档 + 2K；如果某次调用要的档位当前模型没有、而目录里的兄弟模型有，工具会自动改到兄弟模型并在结果里说明，不必先来改设置。

端点下方是 **获取专属 API Key**，目标地址同样来自目录：每个适配器一个厂商控制台/注册页（`ark` → `https://console.volcengine.com/`，`maizi` → 麦子注册页）。本仓库无法为其背书的适配器一律不显示链接，而不是猜一个地址 —— 目前 `mxapi` 就属于这类。

**测试连接**跑在卡片当前显示的值上，包含尚未保存的密钥。探测由该行的适配器自行负责：提供方实现 `probe(draft)`，因为只有它知道哪种请求能证明自己协议的连通性与密钥可用性。适配器未挂载、或该提供方未实现探测时，回落到路由自带的通用端点探测。

结果是**三态**而非布尔：

| 状态 | 含义 | 显示 |
|---|---|---|
| `ok` | 端点有应答且接受了该密钥 | 绿色 |
| `unconfigured` | 探测能看到的地方都没有密钥：草稿为空、未保存、环境变量兜底也没有 | 中性色 |
| `failed` | 有密钥，但后端拒绝了 | 红色，并带上状态与后端自己的报错原文 |

`unconfigured` 的意义在于：还没人填过的行是"待办"，不是"失败"。把它涂成红色会让"没配置"和"被拒绝"无法区分，也会让人习惯性忽视红色。这个判断由提供方给出，因为只有它知道自己的凭据引用；通用兜底探测（只看表单与已存文档）只检查这两处，并在消息里说明。两种探测都是只读的 —— OpenAI 兼容那条读 `GET /models`，音乐那条查询一个不可能存在的任务 id —— 因此点测试永远不会产生计费生成。行首的密钥圆点同理：未保存密钥时是灰调，不再是红色。

**模型候选**来自同一个适配器，只是更深一层：能枚举模型的后端实现缝上的可选方法 `listModels(signal)`；为了让尚未保存的密钥也能浏览目录，还可实现 `listModelsWithDraft(draft, signal)`。两者都按结构检测，因此没有模型列表接口的后端直接省略它们，该行保留自由文本输入。

<a id="understand-the-implementation"></a>
## 了解实现

宿主机半场用 schemastery schema 注册命名空间，并通过 `/api/roubaai-video` 下的自有路由提供服务，而不是走 harness 的设置 RPC：后者只向配置客户端提供白名单命名空间，第三方命名空间只能通过这种方式到达浏览器界面。该路由被限制为同源请求，暴露四个方法——`settings.get`（脱敏值、修订号，以及本次部署挂载的适配器目录）、`settings.update`（回显修订号的写入）、`test`（针对卡片草稿的连接探测）、`models.list`（某一行后端的模型目录，同样针对草稿，因此尚未保存的密钥也能先浏览目录）。探测与目录读取必须在服务端运行，这是由其性质决定的：两者都需要明文密钥，而明文密钥绝不过线。

`models.list` 返回 `{ models: [{ id, label?, status?, taskTypes?, capability? }], message? }`，其中 `capability`（可用档位、像素下限、参考图上限、支持比例）由宿主半场就地补上 —— 只有它手上有一个活的提供方，浏览器因此不会出现"模型来自一次读取、能力来自另一次读取"这种不一致。三种结果都是刻意设计的：未实现目录调用的后端返回空列表加一句说明（而不是报错，表单据此保留自由文本输入）；本次部署未挂载的适配器被拒绝；后端自身的失败原样抛出 —— 密钥退役或端点不可达必须保持可读，而不是被压扁成「没有模型」。

浏览器半场只 import 本包那个无依赖的 `shared` 模块，因此不会有 schema 库进入客户端包。它注入一个 `settings.section` 插槽占位者，并与那条受限路由通信。

与提供方之间的契约刻意只停留在数据层面：它们按名字读取命名空间并取四个字段，不 import 本包。从未打开过设置页的部署完全不受影响——提供方会回落到凭据存储与环境变量。

<a id="model-experience"></a>
## 模型体验

无。本包只持有提供方配置命名空间与它的设置页面，不注册任何工具、提示词区块或工具参数。

#### KV Cache effect

无；本包既不组装也不发送提供方请求。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与未决工作

- 一个命名空间覆盖所有读取它的提供方，因此若想让图像与视频使用不同端点，就需要第二个命名空间。
- 连接测试只能证明密钥通过鉴权且服务有应答；某个具体模型对该密钥是否可用，由模型选择控件的目录给出——不支持列模型的后端则无从验证。
- 模型选择控件只作建议，不做强制。手工输入的 id 一律接受，因为厂商目录可能滞后于它已为该账号开通的模型。旁边的档位控件才是强制的那一半：可选项只有所选模型自报的档位，模型已不再支持的历史值也不会被保存。
- 页面不展示提供方上报的费用；账本按每次生成记录。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者工作上下文 —— 点击展开</summary>

命名空间放在宿主机平面，是因为设置命名空间是进程级单例：若由提供方行注册，它就会随着该行所在的按会话 realm 一起出现和消失。

路由刻意限制为同源请求。它只返回密钥的**存在性**而非其值；写入必须回显上一次读取返回的修订号，因此过期表单无法静默覆盖较新的密钥。

</details>
